# ADR-0005. Блокировка вводится поэтапно, Device Owner — отдельным решением

- **Статус:** принят; Device Owner отложен владельцем 2026-08-14
- **Дата решения:** 2026-08-12
- **Записан задним числом:** 2026-08-27 — восстановлен по уставу и проверкам на телефоне
- **Решение владельца:** да, 2026-08-12; отсрочка Device Owner — 2026-08-14

## Контекст

Жёсткость блокировки — самое необратимое место проекта. **Снять Device Owner можно только сбросом к заводским настройкам**, а зависший Lock Task запирает телефон целиком. При этом граница возможного задана системой, а не нами:

**Достижимо:** экран поверх всего и локскрина, полная яркость, экран не гаснет; Home/Recents/Back — через Lock Task; шторка, запрет удаления и Safe Mode — только с Device Owner.

**Недостижимо ни одним публичным API:** меню питания по долгому нажатию (SystemUI рисует его поверх любых оверлеев, а `ACTION_CLOSE_SYSTEM_DIALOGS` приложениям запрещён с Android 12) и аппаратная перезагрузка удержанием кнопки.

## Решение

**Этапами, и следующий этап включается только после обкатки предыдущего.**

1. Сначала — главная концепция: зацеп → показ экрана → выключение.
2. Затем Lock Task; **Device Owner — отдельным решением владельца**, не раньше чем fail-safe обкатан (ADR-0004).
3. **Замена блокировке — сделать перезагрузку бессмысленной.** Состояние «не выключен + дедлайн» лежит на диске, `BOOT_COMPLETED` поднимает экран через пару секунд после загрузки. Уйти можно только выполнив условие или сняв тревогу по кабелю.

⚠️ **Device Owner отложен** (владелец, 2026-08-14): назначение требует телефона без аккаунтов, сносить их слишком муторно. Код написан и включается одной командой, когда владелец захочет. Вместо него — «Администратор устройства»: запрет удаления приложения, выдаётся тапом, аккаунты не трогает.

⚠️ **Блокировка сделана не как «нельзя уйти», а как «уход отменяется».** Закрепления экрана на HyperOS 3 **не существует** (проверено 2026-08-14: ключа `lock_to_app_enabled` нет ни в `secure`, ни в `global`), поэтому `startLockTask()` без Device Owner на этом телефоне не делает ничего. Отсюда два слоя: сервис каждые 400 мс проверяет, что экран тревоги впереди, и кладёт оверлей; служба спецвозможностей делает то же по событию смены окна, и её окно не прячется там, где система прячет обычный оверлей.

⚠️ **Системный тумблер «Закрепление экрана» нельзя включить по кабелю:** `WRITE_SECURE_SETTINGS` Xiaomi отдаёт только при входе в Mi-аккаунт.

## Последствия

- В настройках есть тумблер «Блокировать экран тревоги» — аварийный клапан, по умолчанию включён.
- Второй слой опционален: нет разрешения спецвозможностей — работает первый.
- Пока Device Owner выключен, шторку уведомлений и удаление приложения закрыть нечем. Принято сознательно.

## Что отменит это решение

Согласие владельца на чистый телефон под Device Owner — тогда новый ADR с порядком включения и проверенным путём выхода.
