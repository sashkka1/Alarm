# ADR-0011. Приложение на компьютере уезжает в свой проект «Sashboard», Alarm ложится внутрь подмодулем

- **Статус:** ✅ **исполнен 2026-08-26**
- **Дата:** 2026-08-26
- **Решение владельца:** да, прямыми ответами на прямые вопросы, 2026-08-26 (имя «Sashboard», копия протокола, submodule, перенос данных, документы обоих проектов)
- **Меняет:** строку «Агент на компьютере» в каноническом стеке Alarm; модуль `:desktop` из проекта Alarm исчезает
- **Не меняет:** механизм освобождения телефона, формат журнала, протокол обмена по сети

## Контекст

Приложение на компьютере родилось как вкладка статистики будильника и жило модулем `:desktop` внутри проекта Alarm, деля с телефоном общее ядро `:core`. Пока оно показывало подъёмы, это было верно.

Дальше владелец сказал, чем оно станет: **сборкой всех его подпроектов** — локальная модель и чат с ней, звук, что появится потом, и Alarm где-то там же, наравне с остальными. Продукт, который перестаёт быть про будильник, не может жить внутри будильника: его репозиторий, его история и его устав оказываются подчинены чужой теме.

Отсюда две задачи сразу: развести проекты и **не порвать то немногое, что их связывает**.

## Что их связывает на самом деле

Разбор показал: `:desktop` тянул из `:core` 27 классов, но общими с телефоном были **шесть**, и все они — один и тот же предмет, **протокол журнала**:

| Файл | Что держит |
|---|---|
| `LogEvent.kt` | событие, его тип (`EventType`), значения (`LogValue`) |
| `LogCodec.kt` | строка ↔ событие |
| `LogWire.kt` | порты, приветствие, конец пачки, ответы |
| `SleepCycleCsv.kt` | разбор выгрузки Sleep Cycle |
| `Json.kt` | разбор JSON, на котором стоит `LogCodec` |

Остальные 21 — память, речь, отчётные сутки, своды — телефон не использовал вовсе. Они не общие, они просто лежали не там.

## Решение

1. **Новый проект `Sashboard`** — свой репозиторий, приватный. Внутри `:core` (правила и разбор) и `:app` (Compose Desktop). Модуль `:desktop` из Alarm удалён.
2. **21 файл переехал** в `Sashboard/core` вместе со своими тестами. Из Alarm удалён.
3. **Шесть файлов протокола скопированы.** Копия, а не общий модуль: см. «Что при этом теряется».
4. **Alarm лежит внутри Sashboard подмодулем git** и остаётся самостоятельным публичным репозиторием. `git clone --recursive` приносит всё; Alarm клонируется и отдельно.
5. **Данные (`data/`) и движок речи (`runtime/`) переехали** в Sashboard — за приложением, которое их читает и пишет.
6. **Вкладка «Документы» показывает оба проекта**: свои разделы и разделы каждого подпроекта, подписанные его именем.

## Почему копия, а не общий модуль

Рассматривались три пути. Владелец выбрал первый.

| Путь | Цена |
|---|---|
| **Копия в обоих проектах** | формат замораживается, правка требует ручной парной правки |
| Третий репозиторий на протокол | третий репозиторий и возня с submodule ради пяти файлов |
| Пока один репозиторий | отдельным проектом на GitHub не залить — то есть задача не решена |

Решающим было то, чем продукт станет: Sashboard задуман **не связанным** с Alarm, и тянуть между ними общий модуль вечно — дороже, чем один раз заморозить протокол из пяти файлов, который и так не менялся месяцами.

## Что при этом теряется

Осознанная плата, зафиксированная явно:

- 🔴 **Копии протокола расходятся молча.** Ни компилятор, ни тесты этого не увидят: каждая сторона собирается сама по себе и сама по себе зелёная. Проявится потерянными данными — телефон отправит то, что компьютер не разберёт.
- Отсюда правило [P0] в уставах **обоих** проектов: правишь любой из шести файлов — правь и на другой стороне, в том же заходе.
- Работа над сквозной задачей теперь идёт в двух репозиториях и требует двух коммитов.

## Порядок — как у ADR-0007, и по той же причине

В цепочке освобождения телефона участвует `Escape.kt`, который переезжал вместе со всем остальным. Разрыв между «убрали старое» и «работает новое» — это интервал, в котором владелец не может освободить телефон, и он должен быть нулевым.

1. ✅ Sashboard собран рядом, `Alarm/desktop` при этом не тронут.
2. ✅ **Проверено на живом телефоне 2026-08-26.** Тревога поднята (со звуком и вибрацией, выключенными на время проверки, и возвращёнными сразу после), затем снята новой сборкой: `Sashboard.exe --alarm-off` ответил «телефон свободен — по кабелю (cucujzeep7guhiz5)», `runStartedAt` ушёл в ноль, `AlarmActivity` покинула передний план.
3. ✅ Только после этого `desktop/` удалён из Alarm.

Промежутка, в котором владелец не мог бы освободить телефон, не было.

## Проверено

- `:core:test` Sashboard — **168 тестов в 13 классах, ноль падений**.
- `:app:compileKotlin` Sashboard — чисто, без предупреждений.
- Упаковка `:app:pack` — `builds\Sashboard\Sashboard.exe` собирается.
- Alarm после удаления: `:core:test` зелёный, `:app`, `:platform`, `:ui` компилируются.
- Цепочка освобождения — на живом телефоне, см. выше.
