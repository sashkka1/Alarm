# Карта работ: запись ночи по звуку

⛔ **Направление закрыто 2026-10-14:** запись ночи удалена из приложения по слову владельца — `docs/zapis-nochi.md`. Вердикты ниже — история.

Одно направление работы — одна такая страница. Здесь состояние и вердикты.

**Зачем это вообще.** Владелец хочет со временем сделать свою замену Sleep Cycle — разбирать сон по звуку самостоятельно. Чтобы было на чём это строить и с чем сравнивать, нужны настоящие записи своих ночей: «что записали мы» против «что показал Sleep Cycle». Пока задача ровно одна — **накопить ночи**. Никакого разбора приложение не делает и не должно.

## Проверить руками

1. **Записать настоящую ночь.** Нажать «Записать ночь» перед сном, утром дать Sleep Cycle зазвонить как обычно. Наутро проверить: файл на месте, длится всю ночь, в журнале `night.record.finished` с `reason: ring`.
2. ⚠️ **Место на телефоне.** Ночь весит около **900 МБ**. Перед сном стоит убедиться, что свободного места хватает: если оно кончится посреди ночи, запись оборвётся (в журнале будет `reason: error`), а записанное до того — уцелеет.
3. **Забрать записи на компьютер** — попросить Claude, он скачает по кабелю. Отдельной передачи по сети нет намеренно: гигабайт по протоколу журнала не ходит.

## Что делать дальше

- Накопить несколько ночей, прежде чем браться за разбор.
- Решить, где записи хранятся на компьютере и надо ли их чистить с телефона автоматически (сейчас не чистятся вовсе — копятся, пока владелец не удалит).
- Разбор сна по звуку — отдельное направление и отдельная страница, когда дойдёт до него.

## Как это устроено

| Слой | Что делает |
|---|---|
| `core/NightAudio.kt` | правила: частота, заголовок WAV, крайний срок, имя файла. 18 тестов |
| `platform/NightRecorder.kt` | микрофон → файл. Ничего не решает, только пишет |
| `app/NightRecordingService.kt` | служба переднего плана с типом `microphone` |
| `app/NightDeadlineReceiver.kt` | девять утра |
| `app/NightRecordTestReceiver.kt` | запуск по кабелю — иначе проверить нечем |

**Файлы лежат** в `files/night-audio` внутри приложения, забираются кабелем:

```
adb exec-out run-as com.sasha.alarm cat files/night-audio/<имя>.wav > <куда-то>.wav
```

**Формат:** WAV, 16 кГц, моно, 16 бит, без сжатия — примерно 115 МБ в час. Сжатия нет намеренно: кодек с потерями первым выбрасывает тихое, а тихое здесь и есть предмет будущего разбора.

**Запись останавливает первое из трёх:** зазвонил будильник (свой или Sleep Cycle), настало девять утра, нажата кнопка.

## Журнал заходов

### 2026-08-26 — сделали запись ночи

**Просьба владельца:** «приложение должно слушать и записывать всю ночь… в дальнейшем хочу сделать копию Sleep Cycle, именно слушать всю ночь, на основании звука анализировать. Поэтому мне нужно записать несколько своих ночей, чтобы потом сравнивать». Кнопка, не автоматически: «автоматически некорректно, просто на главный добавить кнопку». Нажал — закрыл телефон — запись продолжается; кончается, когда прозвонит будильник. Хранить пока просто на телефоне, перекачивать по просьбе.

**Решения владельца в этом заходе:**

| Вопрос | Ответ |
|---|---|
| Формат | WAV 16 кГц без сжатия (~900 МБ за ночь) |
| Когда встаёт | в момент звонка |
| Где хранится | на телефоне, забирать кабелем |
| Если будильник не зазвонил | крайний срок — девять утра |

**Что найдено при проверке на телефоне (и починено в том же заходе):**

1. 🔴 **Служба перезапускалась сама и затирала запись.** С `START_STICKY` система подняла её через 280 мс после остановки — с пустым намерением, то есть по ветке «начать заново», — и 17 уже записанных секунд были стёрты. Две беды разом: микрофон включился **сам**, чего владелец прямо не хотел, и потерялось записанное. Заменено на `START_NOT_STICKY`: пережить смерть процесса запись всё равно не может, микрофон закрывается вместе с ним.
2. 🔴 **Имя файла точно до минуты**, поэтому два запуска подряд открывали один и тот же файл. Теперь занятое имя получает номер: записанное не затирается никогда.

**Чем проверено:**

- 18 тестов правил в `:core`, включая проверку, что крайний срок всегда в будущем и не длиннее суток.
- Запись 14 секунд владельцем: заголовок WAV разобран по байтам (PCM, 16000 Гц, моно, 16 бит — всё сходится), звук проверен по секундам. Тишина в комнате даёт уровень 3–8, голос — 584–1107, пик 6504 из 32767. То есть микрофон пишет настоящий звук, тихое не прибито в ноль, громкое не срезано.
- Остановка по звонку: тревога поднята (со звуком и вибрацией, выключенными на время проверки и возвращёнными сразу после) — запись встала через **483 мс** с `reason: ring`.
- Три записи подряд легли тремя разными файлами, ни одна не затёрта.

**Что добавилось в протокол журнала:** три события — `night.record.started`, `night.record.finished`, `night.record.failed`. ⚠️ `EventType` лежит копией в обоих проектах, поэтому правка внесена сразу и там и там, а на компьютере они получили человеческие описания во вкладке журнала.
