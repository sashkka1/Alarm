# Карта работ: испытание метками и снятие замка

Метки читаются только на разблокированном телефоне (устав, раздел «Метки читаются только на РАЗБЛОКИРОВАННОМ телефоне»). Поэтому испытание метками начинается с просьбы к системе снять замок — `AlarmActivity.requestUnlockForNfc()`. Эта страница — про то, как этот запрос ведёт себя на живом телефоне и почему утром он может не помочь.

## Проверить руками

- Что именно видно на экране в момент запроса: снимок по кабелю отдаёт чёрный лист с кольцом отпечатка (окно ввода пароля защищённое, `screencap` его не рисует). Нужны глаза владельца: поднять тихий прогон по порядку ниже и посмотреть на телефон в первые пять секунд.

## Как поднять тихий прогон с метками по кабелю

1. Снять копию состояния: `adb shell run-as com.sasha.alarm cat files/alarm-state.json` → в файл.
2. В копии заменить `"soundEnabled":true` → `false`, `"vibrate":true` → `false`, `"challenge":"PUSHUPS"` → `"NFC"`; `adb push` в `/data/local/tmp/`, затем `adb shell run-as com.sasha.alarm cp /data/local/tmp/<файл> files/alarm-state.json`.
3. `adb logcat -c`, затем `adb shell am broadcast -a com.sasha.alarm.TEST_TRIGGER -n com.sasha.alarm/.TestTriggerReceiver --ei seconds 3`.
4. Смотреть: `dumpsys nfc` (`mScreenState`, `mEnableReader`), `dumpsys window` (`mCurrentFocus`), `dumpsys activity service com.android.systemui` (`isBouncerShowing()`, `state: BOUNCER`), `logcat -d -s AlarmActivity:V`.
5. После снятия тревоги (`"runStartedAt":0`) положить исходный файл обратно тем же путём и перечитать: звук, вибрация и испытание обязаны вернуться.

⚠️ Через `cat > файл` из PowerShell не писать — портится кодировка; только `adb push` + `cp` под `run-as`.

**Механизм.** Просьба снять замок, поданная **до того, как HyperOS закончил анимацию перекрытия замка** (~0,9 с после старта экрана), уничтожается в момент её окончания: `handleSetOccluded(true)` сбрасывает окно ввода и шлёт `onDismissCancelled`. В прогоне 13:05 экран поднимался медленнее (заслонка, холодный старт) и просьба ушла в 22.029 — уже после `handleSetOccluded` в 21.912, потому и выжила. Это гонка, а не разное поведение системы: выигрывает тот, кто позже. Отсюда же «то через десять секунд, то никак» из разбора 19 августа — десять секунд это как раз `UNLOCK_RETRY_MS`.

**Правка (владелец разрешил «считать за разрешение к действиям», 13:20).** `AlarmActivity`: просьба снять замок повторяется по `onWindowFocusChanged(true)` — фокус возвращается ровно тогда, когда окно ввода ушло; плюс страховочная проверка раз в `UNLOCK_RETRY_MS` (владелец попросил чаще десяти секунд — поставлено **3 с**), которая просит только при фокусе у нас, чтобы не сбивать ввод пароля; не чаще раза в секунду (`UNLOCK_MIN_INTERVAL_MS`). Колбэк отказа по-прежнему ведёт к повтору. Собрано `alarm-debug-1.100.apk`, поставлено `adb install -t -r`, обе службы привязались.
