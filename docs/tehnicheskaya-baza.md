## 🔬 Как ловим чужой будильник (техническая база)

Задача разбивается на три независимые: **узнать**, **показать своё**, **заткнуть чужое**.

### (а) Узнать
| Источник | Что даёт | Надёжность |
|---|---|---|
| `AlarmManager.getNextAlarmClock()` + broadcast `ACTION_NEXT_ALARM_CLOCK_CHANGED` | **точное время** следующего будильника любого приложения в системе | Высокая, публичный API. Видит только будильники, поставленные через `setAlarmClock()` — так делают практически все (иначе нет иконки будильника в статус-баре) |
| `NotificationListenerService` | момент, когда будильник **реально зазвонил**: пакет, канал, `CATEGORY_ALARM`, наличие full-screen intent, список действий | Средняя: зависит от того, как чужое приложение оформляет уведомление; ломается при его обновлении. Требует разрешения «Доступ к уведомлениям» |
| `AudioManager.registerAudioPlaybackCallback` | факт «что-то играет с `USAGE_ALARM`» | Страховка. С Android 9 имя чужого пакета не отдаётся — только сам факт |

Комбинируем: время берём из `getNextAlarmClock()` и ставим **свой** exact-alarm на ту же миллисекунду (тогда экран поднимется даже если слушатель уведомлений отвалился), а факт звонка и ручку «выключить» — из уведомления.

### (б) Показать своё поверх
- `Activity` с `setShowWhenLocked(true)` + `setTurnScreenOn(true)` + `FLAG_KEEP_SCREEN_ON` + `screenBrightness = 1f`.
- Запуск из фона запрещён с Android 10, поэтому основной путь — **full-screen intent** уведомления на канале с `IMPORTANCE_HIGH` и `USAGE_ALARM` (разрешение `USE_FULL_SCREEN_INTENT`; с Android 14 оно auto-grant только приложениям-будильникам — мы им и являемся).
- **Фолбэк — оверлей** (`SYSTEM_ALERT_WINDOW`, `TYPE_APPLICATION_OVERLAY`). ⚠️ Опыт прошлого проекта: на MIUI и подобных прошивках запуск активити из фона не запрещается явно, а **молча откладывается** — окно всплывает, только когда приложение само выходит на передний план. Поэтому фолбэк включается **и по таймауту** (проверка через ~400 мс: активити не появилась → рисуем оверлей), а не только по исключению.
- Держать процесс живым (foreground service) в окне вокруг будильника, чтобы экран появлялся мгновенно, а не после холодного старта.

### (в) Заткнуть чужое
| Способ | Как | Оценка |
|---|---|---|
| Нажать его же кнопку «Выключить» | из `NotificationListenerService` взять `Notification.Action.actionIntent` и вызвать `.send()` | **Основной.** Чужое приложение корректно завершает свой цикл само |
| Обнулить `STREAM_ALARM` | `AudioManager.setStreamVolume` (нужен доступ к политике «Не беспокоить») | Грубо: вибрацию не гасит, громкость надо возвращать. Только как аварийный |
| Accessibility-сервис жмёт кнопку на его экране | `performAction(ACTION_CLICK)` | Универсально, но топорно и хрупко. Только если первые два не сработали |
| Аудиофокус | `requestAudioFocus(GAIN_TRANSIENT_EXCLUSIVE)` | **Не работает:** будильники намеренно игнорируют потерю фокуса |

⚠️ Чужой snooze/повтор живёт по своим правилам — приложение обязано понимать, что тот же будильник может зазвонить снова через несколько минут.

## 🔒 Блокировка: что физически возможно на Android

Отдельный этап, но границы фиксируем сразу, чтобы не обещать невозможного.

**Достижимо:**
- экран поверх всего, включая локскрин, полная яркость, экран не гаснет;
- Home / Recents / Back не работают — **Lock Task Mode**. Без Device Owner это «закрепление экрана» (теоретический выход хитрым жестом), с Device Owner выхода нет;
- шторка уведомлений отключена, приложение нельзя удалить, Safe Mode запрещён — **только Device Owner** (`dpm set-device-owner` через adb, требует телефона без аккаунтов на момент установки).

**Недостижимо ни одним публичным API:**
- **меню питания по долгому нажатию не заблокировать** — SystemUI рисует его поверх любых оверлеев, а рассылать `ACTION_CLOSE_SYSTEM_DIALOGS` приложениям запрещено с Android 12;
- **аппаратная перезагрузка удержанием питания ~10 с** — прошивка, софтом не останавливается.

**Замена блокировке:** сделать перезагрузку бессмысленной. Состояние «будильник не выключен + дедлайн» лежит на диске абсолютной меткой времени; `BOOT_COMPLETED` поднимает экран через пару секунд после загрузки. Выключить телефон можно — но уйти с экрана всё равно получится только кнопкой или по дедлайну.

**⚠️ Device Owner — необратимо опасен:** зависший lock task запирает телефон целиком, а снять Device Owner можно только сбросом к заводским. Поэтому он включается **только после** того, как fail-safe обкатан на сценариях: краш UI-процесса, убийство приложения системой, перезагрузка во время тревоги, разряд батареи, перевод часов.
